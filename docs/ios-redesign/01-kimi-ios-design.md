# 随记 iOS：纸面上的单一个人流

> 设计与 UI 作者：coding kimi `k3.1-pro-highspeed`
> 日期：2026-11-09
> 对应实现：`ios/PersonalAgent/*.swift`
> 范围：在现有 iOS 最小壳上整体改版；不新增服务端能力，不移植 Android 功能全集。

## 1. 设计命题

**把「写下此刻」与「问回记忆」放在同一张安静的纸面上。**

首版不是聊天窗、任务中心或多 Tab dashboard，而是一条按时间排列的个人流：真实笔记与当前进程内的问答共用卡片语言；需要用户处理的保存异常排在流前，其余健康状态不占额外空间。

借鉴参考中的四个机制，而不复制品牌：

1. **单一个人流**：不在“记事功能”和“问答功能”之间跳页。
2. **少打扰**：没有营销横幅、无意义统计、技术状态或持续 toast。
3. **诚实状态**：接收、读取、整理、回答分别表达；不把请求发出写成完成。
4. **待确认优先**：只有保存未完成、读取失败、回答失败等需要行动的内容被强调。提醒尚未接入，因此不制造“待确认提醒”占位卡。

## 2. 信息架构

```text
未登录
└─ 登录
   ├─ 邀请码输入
   └─ 登录失败：页内原因 + 修改后重试

已登录：个人流（唯一主页面）
├─ 顶部：随记 / 我的个人流 / 刷新 / 设置
├─ 引导：此刻，想留下什么？
├─ 行动区（按需出现）
│  ├─ 原文保存中 / 保存结果未确认 / 明确被拒绝
│  └─ 笔记读取失败
├─ 最近：按时间混合排列
│  ├─ 笔记卡：原文、整理状态、标题、标签、待办、时间
│  └─ 问答卡：问题、回答、来源摘录、失败重试
├─ 空态：插画 + 文字记下 / 切换提问
└─ 固定底部输入坞
   ├─ 记下 / 提问（用户显式选择）
   ├─ 多行文字输入
   ├─ 语音（disabled，原因常驻）
   └─ 记下 / 提问主操作

设置 Sheet
├─ 当前能力：可用 / 未接入
├─ 数据与恢复边界
└─ 退出登录（二次确认）
```

不设置传统 Tab。搜索、笔记详情、编辑、删除、提醒列表、通知和语音层都不伪装成已经存在的二级页。

## 3. 主屏与统一输入

### 3.1 首屏顺序

1. 产品名与设置入口保持轻量，不显示 API 地址、commit SHA、token 或“验证壳”标记。
2. 一句引导说明个人流内容，不显示用户数、在线率或虚构进度。
3. 未完成的创建固定在内容前，防止失败被后续问答淹没。
4. 笔记与问答按记录/创建时间倒序混合排列；刷新不会把回答持久化。
5. 输入坞固定在底部，内容滚动不带走输入入口，也不以悬浮按钮遮住卡片。

### 3.2 两种明确模式

- **记下**：输入 1–5000 字，调用 `POST /v1/notes`。发送后原文先进入“原文保存”卡，而不是立即伪装成服务器笔记。
- **提问**：输入 1–2000 字，调用 `POST /v1/ask`。问题立即成为当前进程问答卡，等待、答案或失败都更新同一张卡。
- 模式只能由用户切换，不做自由意图路由；切换不会清空当前文字。
- 任一网络操作在途时允许继续编辑下一份文字，但禁用发送、刷新、重试和登出；不并行、不自动排队，回来后由用户手动发送。
- 提交时捕获不可变文字快照并清空对应输入；等待期间新输入的文字不会被旧响应清掉。

### 3.3 语音边界

语音按钮实际 disabled，并常驻“语音输入尚未接入，请使用文字。”。按钮提供 VoiceOver hint，不申请麦克风权限、不生成假转写、不以“即将支持”暗示可用日期。

## 4. 视觉系统

核心隐喻是**暖白纸面上的一笔青绿**，不是聊天气泡。

| Token | 值 | 用途 |
| --- | --- | --- |
| canvas | `#F7F3EA` | 页面与输入坞底色 |
| surface | `#FFFDF8` | 笔记、问答、空态卡片 |
| soft | `#E7EEE6` | 模式选择器与插画底层 |
| ink | `#20332D` | 主文字 |
| secondary | `#596B62` | 次文字、未接入能力 |
| accent | `#0E6858` | 主按钮、链接、选中态 |
| accentSoft | `#D5E8DE` | 选中的输入模式 |
| attention | `#984B35` | 保存/整理异常与需要注意的状态 |
| danger | `#9D4141` | 输入错误、退出等破坏性操作 |
| line | `#D9D8CC` | 卡片与输入边界 |

- 系统字体，圆体仅用于主屏引导；正文 16–17pt，卡片标题与状态有明确层级。
- 20pt 卡片圆角、14pt 控件圆角、20pt 页面边距、16pt 卡片间距。
- 主操作最小高度 48pt，设置入口与语音次操作最小高度 44pt。
- 状态不只靠颜色：每枚状态 pill 都有文字；失败附图标和可执行动作。
- 当前实现固定浅色外观，避免未设计的暗色配色被系统自动套用。
- 使用 SwiftUI 动态字体和可增长卡片，不设固定卡高；大字体、对比度和 VoiceOver 仍需 Mac/真机实测，本文不宣称已通过。

## 5. 空态与演示内容

### 5.1 可视觉核验的空态

只有**笔记读取已成功、当前没有笔记/问答、没有未完成创建、没有错误且不处于首次加载**时才显示空态。网络失败绝不能被画成“暂无内容”。

空态包含：

- 暖白卡片上的纸张与青绿加号插画；
- “从一句话开始”与两行明确说明；
- 主操作“用文字记下第一条”，点击切到记下并聚焦键盘；
- 次操作“我想问一段记忆”，点击切到提问并聚焦；
- `accessibilityIdentifier("personal-flow-empty")`，便于 UI 测试定位。

Xcode Preview 提供 **“空个人流”**、**“登录”**、**“示例内容”** 三个独立场景。Preview 是视觉核验入口，不替代模拟器截图或真机验收。

### 5.2 示例不进入真实用户流

所有演示笔记、回答与 citation 只存在于 `#if DEBUG` 的 Preview 工厂。示例场景顶部显示“示例内容 · 仅用于界面预览”，每张示例卡也标“示例”；生产初始化和现网请求不会创建这些数据。

## 6. 状态与恢复契约

| 对象 | 状态 | 首要呈现 | 操作与禁止 |
| --- | --- | --- | --- |
| 登录 | 空闲 | 邀请码输入 | 空邀请码禁用登录 |
| 登录 | 请求中 | “正在登录…” | 防重复提交 |
| 登录 | 失败 | 页内固定文案或安全服务端说明 | 保留邀请码供修改，不伪造成功 |
| 笔记列表 | 首次读取 | “正在读取笔记…” | 不显示空态 |
| 笔记列表 | 成功为空 | 空态插画与文字入口 | 不插入示例 |
| 笔记列表 | 读取失败 | “暂时没能读取全部笔记” | 手动重新读取；不把失败改写成空列表 |
| 创建 | 发送中 | “正在保存原文” | 原文在行动区；不提前进入服务器笔记流 |
| 创建 | 网络失败/结果未知 | “保存结果未确认，服务器可能已接收” | 同一 `client_note_id` 手动重试；不清原文 |
| 创建 | 明确 4xx 拒绝 | 服务端拒绝原因 | “取回编辑”；不盲目重放 |
| 创建 | 202 后读取失败 | “服务端已接收原文” | 只重新 GET 该 note，不再次 POST |
| 创建 | 读取成功 | 真实 Note 进入个人流 | 以 GET 的 `status/title/tags/todos` 为准 |
| 笔记 | `uploaded` | “已保存 · 整理中” | 不显示百分比，不承诺完成时间 |
| 笔记 | `organized` | “已整理”及实际派生字段 | 不声称记忆已可搜索 |
| 笔记 | `failed` | “原文已保存 · 整理失败” | 不提供不存在的“重试整理”接口 |
| 问答 | 请求中 | “正在查找记忆并回答…” | 不并行提问，不自动重试 |
| 问答 | 成功 | 答案与服务端返回的来源摘录 | 仅当前进程可见；无 citation 不补造来源 |
| 问答 | 无相关记录 | 原样显示“我没有相关记录。” | 是有效答案，不标网络错误 |
| 问答 | 失败 | “这次没有拿到答案” | 用户明确点“重新提问”；保留问题 |
| 会话 | 401 | 回到登录页并说明失效 | 清本机会话与当前内容，不跨会话写回 |
| 登出 | 服务端失败 | 回本机登录页并说明服务端未成功 | 本机仍清凭证；不显示完整退出成功 |
| 输入 | 网络忙碌 | 显示当前实际动作 | 可编辑下一稿；发送禁用，不自动排队 |
| 语音/提醒 | 未实现 | disabled / “未接入” | 无权限弹窗、无假进度、无假成功 |

### 创建恢复的有意边界

- `client_note_id` 在一个未完成创建及其重试之间保持不变；新的一次用户提交才生成新 ID。
- 恢复项、草稿、问答只保存在当前进程。进程被终止后没有跨启动恢复，不展示永久“发送中”。
- 这不是完整离线业务缓存，也不是持久创建队列。设置页和 README 明示这一限制。

## 7. 能力矩阵

| 能力 | UI 状态 | 实际接口/行为 |
| --- | --- | --- |
| 邀请码登录 | 可用 | `POST /v1/auth/login` |
| 退出登录 | 可用 | `POST /v1/auth/logout`；网络失败也清本机会话并说明 |
| 最近笔记读取 | 可用 | `GET /v1/notes?limit=50` |
| 单条创建后读取 | 可用 | `GET /v1/notes/{id}` |
| 文字记下 | 可用 | `POST /v1/notes`，5000 字 |
| 整理状态呈现 | 可用 | 只映射 `uploaded / organized / failed` |
| 文字提问 | 可用 | `POST /v1/ask`，2000 字 |
| 回答来源摘录 | 可用 | 显示 `citations` 原文，不跳转未实现的详情 |
| 手动刷新/对象级重试 | 可用 | 仅重试对应读取、创建或问答 |
| 语音记事/语音提问 | **禁用** | 按钮 disabled + 常驻说明；无 ASR |
| 提醒确认、闹钟、通知 | **禁用/不提供入口** | 无对应 iOS 实现，不显示建议卡或排程成功 |
| 搜索、编辑、删除、TTS | **不提供入口** | 本版未接入 |
| 多轮持久聊天 | **不提供入口** | 问答仅存当前进程 |
| 自动 token refresh | **不可用** | 过期后重新登录 |
| 离线完整缓存 | **不可用** | 冷启动仍需读取服务端 |

## 8. 与当前最小壳的差异

| 当前壳（含截图） | 本次改版 |
| --- | --- |
| 首屏大卡片展示“iOS 验证壳”、commit SHA 与完整 API base | 首屏只保留邀请码与产品引导，技术信息全部移出普通 UI |
| 登录、提问、回答、笔记、登出堆叠在同一 List | 未登录/已登录分层；已登录是单一个人流 + 设置 Sheet |
| 只有文本提问，不能创建笔记 | 统一输入坞支持真实文字记下与提问 |
| 笔记显示原始 `status` 字符串 | 显示中文语义状态、标题、正文、标签、待办和时间 |
| 空列表只有“暂无笔记” | 有可操作、可定位、可用 Preview 核验的完整空态 |
| 一个全局“请求中…”和全局错误 | 登录、列表、创建、每张问答卡分别显示忙碌与失败 |
| 提问失败只有错误文字 | 原问题保留在卡中，可明确重新提问 |
| 无语音能力但也没有边界说明 | 语音按钮 disabled，并持续说明使用文字 |
| 登出直接出现在列表末尾 | 轻量设置中二次确认，说明数据影响 |
| 无演示标记机制 | 演示仅用于 DEBUG Preview，并逐卡标“示例” |

## 9. 验收顺序

1. 在 Xcode 打开“登录”与“空个人流” Preview，核对暖白纸面、青绿主操作、固定输入坞与无调试信息。
2. 用有效邀请码登录，确认自动读取真实笔记；用空账户或清空数据后的账户核对空态，不能以断网代替空态。
3. 分别记下与提问，核对真实 Note、答案和 citation；断网时检查原文/问题保留与重试文案。
4. 模拟创建 202 后 GET 失败，确认重试只读取；模拟创建网络未知，确认重试沿用同一创建标识。
5. 检查语音不可点击，设置中语音与提醒均为“未接入”；没有闹钟、通知或权限成功假象。
6. 登出确认后回到登录页；进程重开不应恢复示例、旧问答或未完成创建。
7. 在 Mac 执行构建，并在模拟器/真机补做键盘、大字体、VoiceOver、横屏和实际网络验收。Linux 静态检查不能替代这些项目。
